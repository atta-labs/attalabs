The mechanism

Three enforcement rings around one source of truth.

Vinaya doesn't watch agents and hope. It compiles your engineering process into deterministic checks that run at three fixed points — before code exists, before it merges, and after it ships — all anchored to the one place status actually lives: your GitHub repo.

01 — the model

GitHub is the center. Nothing is stored anywhere else.

Ring 0 — before it exists
Ring 1 — before it merges
Ring 2 — after it ships
R0 Prevent

runs on the agent's own machine

Catches

Malformed commits, missing docs, broken conventions — before the artifact ever leaves the agent's session.

Who pays

Nobody. The agent reads the exact error and self-corrects in-session.

R1 Detect

runs in CI — the guarantee

Catches

Everything, regardless of which tool wrote it — the web UI, the raw API, a human. Same checks, no exceptions.

Who pays

Merge is blocked until it's green. Red means a gate caught something — never a silent failure.

R2 Audit

runs after merge — continuous

Catches

Drift between what shipped and what was decided, across the full history — not just one PR.

Who pays

Never blocks anything. It writes the permanent record — a fact, not a verdict.

02 — one change, start to finish

What actually happens to a single commit

1 — write

Agent makes a change, tries to commit.

→

2 — ring 0

Local hook refuses if it's malformed. Fix, retry.

→

3 — push + PR

Opens against GitHub. The PR is now the review.

→

4 — ring 1

CI runs the same checks again. Must be green.

→

5 — human

Reviews judgment, not compliance. Merges.

→

6 — ring 2

Audit record written. Continuous, never blocking.

03 — who does what

Every role, machine or human, stated plainly

Principal The only one who ratifies irreversible decisions. Final authority. human
Team Leader Plans the work and writes the brief an agent executes against. agent
Developer Executes the brief, writes the code, opens the PR. agent
Reviewer Independent judgment, fresh context — never the agent that wrote the code. agent
Archivist Closes the task out, writes the permanent record. Automated. agent

04 — why github, specifically

Status is derived. Nothing is written by hand.

a branch exists

→ in progress

a PR is open

→ in review

CI is red

→ blocked

the PR is merged

→ done

No status field, anywhere, that a human or an agent writes by hand. Status can't drift, because nothing stores it — it's read fresh from what actually happened, every time.

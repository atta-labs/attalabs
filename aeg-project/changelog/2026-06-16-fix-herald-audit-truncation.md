## June 16, 2026 — Herald audit truncation + stale model + JD charset (Fix)

### Herald
- **Audit truncation (the headline bug).** Every production audit was returning a partial "took longer than expected" report. Root cause was a two-layer max-output-tokens cap that silenced the Skeptical Auditor mid-JSON: the YAML pinned `defaults.max_tokens: 2000`, AND `@atta/adapter-langgraph`'s Anthropic call sites hard-coded `max_tokens: 4096`. Production logs showed the model emitting 3.5k–4k output tokens for a complete report — both caps clipped the JSON, `parseMatchReport` failed twice in the route's retry loop, and `buildPartialReport` ran. Fix is end-to-end: YAML raised to `max_tokens: 8000`; engine's `compileFlow.buildAgents` now propagates `flow.defaults.maxTokens` / per-agent `maxTokens` onto the compiled `Agent`; `@atta/adapter-langgraph`'s three Anthropic call sites (`llm.ts` structured-output path, `llm.ts` free-form path, `custom-tool-loop.ts` per-turn) now read `agent.maxTokens ?? 4096`. Backwards-compatible: every existing Vāda agent has no YAML `max_tokens`, falls through to the 4096 default, behavior is byte-identical. Three pinned regression tests: (a) `parseMatchReport` parses a >16 000-char (>4 200-token) full report; (b) `runAnthropicCustomToolLoop` forwards caller `maxTokens` to `messagesCreate` verbatim and falls back to 4096 when omitted; (c) `herald-auditor.yaml` test asserts `defaults.maxTokens === 8000` AND the compiled `SkepticalAuditor` agent carries `maxTokens === 8000` after `compileFlow`. `parseMatchReport` was lifted out of `app/api/audit/route.ts` into `src/lib/parse-match-report.ts` so the parser can be unit-tested without pulling in `next/server`; the route imports it unchanged.
- **Stale default model.** YAML `defaults.model` was pinned at `claude-sonnet-4-20250514`, which Anthropic now returns 404 for, and the same string lived in two other paths (`route.ts` env-fallback creds at line 262; `audit-key.ts` `DEFAULT_AUDIT_MODEL` at line 40 + module docstring at line 12). All four updated to `claude-sonnet-4-6`. The auditor YAML test's model assertion was updated in lockstep. Free side benefit: the adapter's `PRICING` table already has `claude-sonnet-4-6` (input $3 / output $15 per million), so the long-standing `$0.00` cost readout for every Herald audit (Herald backlog item, AEG task 9 cost-table dependency) now resolves to real numbers without a separate fix.
- **JD URL charset/encoding (mojibake).** `audit-input/url-fetch.ts:fetchAndExtractText` decoded every response body as UTF-8 regardless of the page's actual charset. Real-world JD pages (e.g. the Binance careers page) serve windows-1252 or ISO-8859-1 and came through as `worldâs`, `Binanceâs`, `â¢ bullet` — the LLM was reading garbage. New `parseCharsetFromContentType` reads `charset=…` from the Content-Type header; new `detectCharsetInHtmlPrefix` scans the first 1 024 bytes for `<meta charset="…">` and `<meta http-equiv="Content-Type" content="…; charset=…">`; new `decodeBody` chains them with UTF-8 as the final fallback (and a safety try/catch around unknown labels so the route never throws on a typo). The five-layer SSRF pipeline is untouched — encoding detection runs after the body is read into the size-capped buffer, so the syntactic / DNS / IP-pinning / redirect / size-cap defenses still gate the bytes that reach the decoder. 11 new unit tests cover header parsing, meta-tag detection, the windows-1252 mojibake repro fixture, meta-tag fallback when the header is silent, default-to-UTF-8, and unknown-label graceful degradation. All 21 existing SSRF tests still pass unchanged.
- **Audit LLM timeout 45s → 90s.** With the YAML cap raised to 8 000, Sonnet's non-streaming wall-time for the synthesis turn (~4 000 real output tokens at ~80 tok/s) plus the custom-tool loop's first turn + the 3 s GitHub fetch regularly cleared the previous 45 s `AUDIT_LLM_TIMEOUT_MS` and re-triggered the "took longer than expected" partial-report fallback at runtime (verified on Dani's live dev session against the live branch, June 17). Bumped to 90 s — the 2-turn loop's worst-case (slow vendor + max-headroom output) fits inside the window while spinner-of-death stays capped at a tolerable UX boundary. Comment in `route.ts` records the timeline (25 → 45 → 90) so the next bumper sees the history. The 45 s value was tuned for the pre-truncation-fix world; the new value is correct *for the post-fix output regime* — not a regression, an accompanying widening of the LLM budget the larger cap requires.
- **Tier 1.** Cross-package: Herald (YAML, route, audit-key, parse-match-report extraction, url-fetch encoding, tests, runtime timeout) + `packages/engine` (`compile-flow.ts` propagation, `Agent.maxTokens`) + `packages/adapter-langgraph` (three call sites + custom-tool-loop param). Vāda unaffected — additive only, every existing agent lacking `maxTokens` keeps the 4096 default.

### AEG
- **PR-body canonical form (forge-agnostic).** Agents (claude-code, codex, anything next) have repeatedly opened PRs that failed the `verify-docs` Tier gate by writing `Tier 1` instead of `Tier: 1` / `**Tier:** 1`. The contract was scattered across `roles/developer.md:46`, `state-machine.md` §9, and the `verify-docs` regex with no single verbatim block any agent could copy. Fix is methodology-internal — a new `## PR body — canonical form` section in `aeg-root/roles/developer.md` carries the **verbatim, copy-pasteable** PR-body template: `## Summary` / `## Test plan` (each item tagged `[agent]` or `[principal]` — interlocks cleanly with task 10's Verification phase) / `## Scope` ending with `**Tier:** 0 | 1 | 3` on its own line. A field-rules table pins the exact `Tier:` syntax (`Tier: 1`, `**Tier:** 1`, `**Tier**: 1` accepted; `Tier 1`, `Tier-1`, `Tier:1` rejected). `state-machine.md` §9 picks up a one-line cross-reference so the field shape and the gate definition live one click apart. `roles/developer.md`'s prior line 46 prose collapses to a back-link to the canonical section. **Single source of truth, no GitHub artifact, no Claude-runtime anchor.**
- **`scripts/verify-docs.ts` C0 error message** now points the failing author at `aeg-root/roles/developer.md` § PR body — canonical form instead of restating the regex. The failure loop becomes self-healing: CI fails → reads the new message → opens the role doc → copies the verbatim block → next PR passes first try.
- **Two leaky model references to generated views (D-039 hygiene).** `aeg-root/iterations/aeg-ui-v1.md:156` cited `.claude/skills/brief-authoring/SKILL.md` (the generated view) as the file Task 10 edits — repointed to the canonical `aeg-root/skills/brief-authoring/SKILL.md`, with a parenthetical noting `.claude/` is regenerated by `aeg generate-skills` (D-039). `aeg-root/skills/brief-authoring/SKILL.md:240` cited `~/.claude/settings.json` as the permission-prompt example — generalized to "whichever agent runtime is dispatched: most coding-agents expose a permission/auto mode in their own settings store." Same point, tool-agnostic. Net: `grep -rn "\.claude/\|\.github/" aeg-root/` now returns only references where AEG **owns the design of** the artifact (D-039 banners, scaffolded enforcement layer locations); no remaining reference points at a generated view as authority. **Methodology depends on `aeg-root/` only.**
- **Mandatory forge check in the session-start protocol.** Added a new subsection to `aeg-root/coordination.md` § Session start protocol: before producing any brief, audit finding, or "next steps" recommendation, the role must fetch `gh pr list --state open` and `gh pr list --state merged --limit 20`. **Forge state > file state > memory.** This session surfaced exactly the failure mode the rule prevents — I produced an audit referencing a stale state of the iteration without first checking what was actually in flight on the forge. The rule sits next to the spec-check gate so both hard preconditions live in one place.
- **Tier 3, Type 1** — touches the Developer-role contract every iteration depends on. Decision log entry coming with the next AEG ratification.

## July 5, 2026 — Task 35: Fix task 31's broken Vercel skip (no origin remote)

### AEG / Vāda / Herald / Atta / AttaLabs

- **Fix-of-a-fix (#409, closes task 31's #395-item-1 gap)** — task 31's Vercel shallow-clone fix never worked in production: it prepended `git fetch … origin` commands to every `ignoreCommand`, but Vercel's build container configures **no git remote at all** (proven live, 2026-07-05, via a diagnostic deployment: `git remote -v` is empty, git config carries no remote/credential entries, and the checkout's only local ref is `refs/heads/master`). Both fetches failed instantly (`fatal: 'origin' does not appear to be a git repository`), silently (`|| true`), `turbo-ignore --fallback=main` still couldn't resolve `main`, failed open, and every app built on docs-only PRs — the exact behavior tasks 22 and 31 both meant to eliminate. Task 31's "proven in a local depth-10 single-branch clone" verification was the trap: a local clone always has `origin`; only a real deployment shows Vercel's actual checkout shape.
- **Why no fetch can ever work there** — the repo is private and the build container has no ambient git credentials (URL-probe fetches fail with `could not read Username`). Deepening or materializing `main` is therefore impossible by any spelling — named remote, URL, or `git remote add`. The comparison base must be a ref that already exists locally.
- **The fix** — all four `ignoreCommand`s now call one shared script, `scripts/vercel-ignore-build.sh <package>` (this logic had been patched three times across four inline copies), which runs `npx turbo-ignore <pkg> --fallback=HEAD^1`. `HEAD^1` is Vercel's own documented Ignored Build Step for Turborepo and always resolves in the shallow clone. On non-first pushes turbo-ignore diffs against `VERCEL_GIT_PREVIOUS_SHA` as before (note: a *canceled* deployment does not set it — observed live). The dead fetch preamble is removed, not kept as unreachable config. A second live constraint discovered on the way: Vercel schema-rejects any `ignoreCommand` longer than 256 characters.
- **Known limit (accepted, fail direction is safe-for-production)** — on a branch's *first* push with multiple commits, `HEAD^1` compares only the tip commit, so an app change buried in a non-tip commit can miss its preview build (never a wrong production skip: `main` pushes are squash-merges where `HEAD^1` is exactly the pre-merge tip, and production carries previous-deployment SHAs). AEG's push-per-Part discipline makes multi-commit first pushes rare.
- **`turbo-ignore` deprecation, weighed and deliberately kept** — turbo-ignore's log recommends Vercel's built-in project skipping. That feature cannot express this repo's main skip case: changes outside the workspace definition (`aeg-root/**` — every docs-only governance PR) are treated as *global* changes that deploy **all** apps, while turbo-ignore's package-graph diff correctly ignores them. Migration rejected on semantics, not effort.
- **Verified against real deployments, not local simulation** — (1) diagnostic deployment logged the container's actual remote/credential state; (2) the fix branch's own push shows `Falling back to ref HEAD^1` → real analysis → correct *proceed* (its diff touches every app's `vercel.json`); (3) a fresh throwaway branch's first push with a docs-only tip — the exact #408 failure shape — shows a genuine skip across all three Vercel projects. Log excerpts in PR.
- **Surface:** 4× `vercel.json`, `scripts/vercel-ignore-build.sh` (new), this changelog entry. `aeg-root/enforcement.md` checked — no row claims the Vercel skip mechanism is verified/working, nothing to correct. Tier 1. Closes #409.
